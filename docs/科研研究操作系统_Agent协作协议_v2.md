# 科研研究操作系统：Agent 协作协议 v2（AI-first 精简版）

## 0. 核心原则

本工作簿只保存 **AI 事后不能可靠还原、但对研究判断很重要的信息**。

因此：

- 人负责：实验前判断、预测、为什么值得做、重大决策、真正的反思。
- Agent 负责：整理、链接、实验事实提取、结果摘要、发现冲突、草拟认知更新。
- Codex / W&B / MLflow / Git 负责：完整实验日志、参数、曲线、checkpoint、代码版本。
- Obsidian 负责：自由思考、长篇笔记、文献阅读与推导。

不要把机器已经有的数据重新手抄进 Excel。

---

# 1. 四张表的职责

## 01_课题总览

这是 Agent 进入课题后的第一读取页。

只记录：

- 课题目标；
- 当前阶段与主线；
- 当前会影响研究决策的条件；
- 当前最重要的判断、未知与风险；
- 当前最重要的三个问题；
- Git / Codex / 实验报告目录 / W&B / Obsidian 等高频入口。

不要把完整文献库、训练参数或所有历史条件变化塞进这里。

---

## 02_想法与候选实验

这是 Idea Inbox + Hypothesis + Experiment Gate 的合并页。

### 新想法出现时

刚产生想法，只需要记录：

- 原始想法；
- 为什么有意思 / 想解决什么。

其余字段可以稍后补。

Agent 可以根据聊天、Obsidian 笔记、论文阅读等草拟：

- 研究问题 / 假设；
- 最小可行验证；
- 替代解释；
- 更便宜的验证方式。

### 禁止

Agent 不得因为以下原因自动把想法升级为实验：

- 很容易实现；
- 文献中常见；
- GPU 空闲；
- 可能涨一点；
- “多做一个消融总没坏处”。

状态统一使用：

- 收件箱
- 待思考
- 值得实验
- 已进入实验
- 暂缓
- 否决

---

# 2. 核心页：03_核心实验记录

这是整个系统最重要的页面。

一行代表一个 **有研究意义的实验比较**，不是一个 seed、一个 learning rate 或一条训练 run。

例如：

正确：
- Random-init vs CT-pretrained
- Global-only vs Local-only vs Global+Local
- Recurrent state vs no recurrent state

错误：
- seed=1
- lr=1e-4
- epoch=80

运行级细节放在 Codex / W&B / MLflow / Git。

---

# 3. 实验前：黄色区域

黄色区域是整套方法的核心。

## 3.1 最低要求

探索实验至少认真填写：

- 对应问题 / 假设；
- 为什么现在值得做；
- 核心对照 / 最小设计；
- 我的预测；
- 继续 / 停止条件；
- 预测锁定时间。

正式验证实验再进一步填写：

- 预测依据；
- 明显成功意味着什么；
- 无明显变化意味着什么；
- 明显失败意味着什么；
- 预计成本。

## 3.2 Prediction Lock

一旦填写“预测锁定时间”，并且实验已经开始：

**禁止修改黄色区域。**

尤其不能在看到结果后修改：

- 我的预测；
- 预测依据；
- 成功 / 中性 / 失败结果的含义；
- 继续 / 停止条件。

如果实验设计真的发生改变：

- 不覆盖原记录；
- 新建实验行，或在最后备注中说明偏差。

目的：

> 防止 hindsight bias，以及 AI 在结果出来后自动编出“其实早就预料到了”的解释。

---

# 4. 实验完成后的标准接口

推荐 Codex 每次实验结束后生成一份标准实验报告，例如：

`experiments/E-023/report.md`

或：

`实验记录/E-023_实验名称.md`

Excel 的 `实验报告MD / 结果链接` 列只保存路径或链接。

## 报告建议至少包含

- 实验 ID；
- 代码 / commit；
- 实验配置；
- baseline；
- 实际指标；
- 关键曲线 / 图；
- 异常情况；
- 与 baseline 的差异；
- Codex 的初步分析；
- 结果文件路径。

Excel 不重复保存这些细节。

---

# 5. 蓝色区域：Agent 自动回填

当 Codex 报告出现后，Agent 应读取报告并自动或半自动填写：

- 状态；
- 实验报告链接；
- AI 提取结果摘要；
- 关键实际变化。

这些是 **事实层**，不需要用户重新抄写。

Agent 必须区分：

> 事实 ≠ 解释

例如：

事实：
- Dice +0.8
- Recall 基本不变
- HD95 改善 0.4 mm

解释：
- “标签边界可能不是主要瓶颈”

解释不能混进事实摘要中。

---

# 6. 绿色区域：人只确认高价值认知

Agent 可以根据实验前预测与实际结果草拟：

- 是否符合预测；
- 最大 Surprise；
- Belief Update；
- 下一步决策；
- 下一研究问题。

但这些属于 **认知层**。

默认流程：

1. Agent 草拟；
2. 用户确认或修改；
3. 才成为正式记录。

用户不需要为每个实验写长篇实验总结。

通常只需要回答：

> 哪里最出乎意料？  
> 我的哪个判断应该增强或减弱？  
> 下一步还值不值得继续？

---

# 7. Agent 的标准实验后流程

收到“实验跑完了”时：

1. 找到对应实验 ID；
2. 读取该实验的 Prediction Lock 区域；
3. 读取 Codex 的实验报告 MD；
4. 提取事实并回填蓝色区域；
5. 将 Actual 与 Prediction 对比；
6. 草拟最大 Prediction Error / Surprise；
7. 草拟 Belief Update；
8. 草拟下一步决策；
9. 提醒用户只确认绿色区域；
10. 禁止回改黄色区域。

---

# 8. 推荐实验时的最低检查

Agent 推荐一个实验前，至少检查：

- 它对应什么研究问题？
- 为什么是现在？
- 不同结果是否会导致不同认知或下一步？
- 是否存在更便宜的最小验证？
- 是否曾经做过类似实验？
- 是否只是常见模块拼接？
- 是否只是为了“再刷一点”？
- 如果这是 Optimize，当前主方向是否已经有足够证据值得优化？

如果一个实验出现：

> 成功、失败、不变，最后都只是“再调一调”

那么它的信息价值很低。

---

# 9. 04_决策与复盘

这一页是低频页。

## 重大决策

只有路线级变化才记录，例如：

- 停止继续做 decoder 小改动；
- 主线从 architecture optimization 转向 representation；
- 某条路线正式 Pivot；
- 某方向暂停直到出现新数据 / 新算力 / 新证据。

普通实验涨跌不需要进入这里。

## 阶段复盘

建议每 2–4 周或重大节点填写一次。

重点回答：

- 最大认知变化是什么？
- 哪个实验最值钱？
- 哪个实验最浪费？
- 如果重来，哪些不跑？
- 是否已经出现“局部刷点”？
- 下一阶段最重要的三个问题是什么？

Agent 可以先生成阶段摘要，但由用户确认。

---

# 10. 权限边界

## Agent 可自动写

- 实验状态；
- Codex 报告链接；
- 实验事实摘要；
- 指标变化；
- 高级入口链接；
- 阶段摘要草稿。

## Agent 可草拟、用户确认

- 研究问题 / 假设；
- 替代解释；
- 更便宜的实验方案；
- 是否符合预测；
- Surprise；
- Belief Update；
- 下一步实验或 Pivot 建议。

## 人工所有

- 最终 Prediction；
- Prediction Lock；
- 高成本实验是否正式启动；
- 重大路线决策；
- 已锁定的实验前判断。

---

# 11. 推荐信息流

```text
聊天 / Obsidian / 文献 / 临时想法
        ↓
02_想法与候选实验
        ↓
值得继续？
        ↓
03_核心实验记录：先写预测
        ↓
Prediction Lock
        ↓
Codex 执行实验
        ↓
Codex 输出实验 MD
        ↓
Agent 自动提取事实
        ↓
用户只确认 Surprise / Belief Update / Next Decision
        ↓
必要时更新 01_课题总览
        ↓
出现路线级变化时写入 04_决策与复盘
```

---

# 12. 最重要的使用原则

这套系统的目标不是让研究记录“更完整”，而是：

> **减少无价值记录，把人的注意力集中到 AI 不能代替的判断上。**

优先保存：

- 我为什么觉得它值得做；
- 我在结果出来前预测了什么；
- 结果哪里真的让我意外；
- 我的研究世界观因此改变了什么。

其余内容尽量交给 Agent、Codex 和外部实验追踪工具。
