# Frozen A-R EF spatial readout

Purpose: check if a readout that sees the pre-mean spatial tokens improves EF on an unchanged, frozen A-R SSL epoch-400 checkpoint. Only two new heads are fitted. No SSL, fine-tuning, extra windows, changes to recurrence, or segmentation.

- C0 is Stage A2's `H/ef_pool_frozen` result, with identical A-R source, original EF cohort and L1 head recipe. Only frozen VAL is available for C0; fine-tuned TEST is not a substitute.
- C1 reads the original final 64 frame descriptors (mean over the 14x14 grid). C2 reads all 196 positions at each of those same 64 frame indices, with the original recurrent state updated across four chronological L16 clips and reset per video. Neither sees frames outside W64. There is no preassigned ED/ES or per-clip query.
- Both heads use a shared architecture and parameter count: 4 queries, width 192, 4-head cross-attention, two query-only self-attention blocks, and an EF regressor. Both add the same fixed temporal sinusoids to the input keys; only C2 adds centered separable 2D sinusoids. The large token set never attends to itself.
- Cache extraction runs the frozen backbone in eval FP32, checks C1 against the existing extraction path, and checks that tubelet2 partners are identical and the spatial grid is not repeated means. The two repeated maps per tubelet are stored once as FP16, restored after the input projection. C1 retains the FP32 mean as a small sidecar computed from the same extraction before quantization. Storage quantization error is recorded. At 8,706 windows the two mmap views take about 40 GiB total; the dense cache is not loaded for C1. TEST streams a single shared extraction, then sends it to both heads after their VAL checkpoints are locked.
- The optimizer and checkpoints contain only the head. The immutable encoder and recurrent parameters are checked before/after fitting. The engine inherits the Stage A2 frozen EF settings: L1 EF loss in pp, AdamW (LR 1e-5, WD 1e-4), effective batch 32 and exactly the same window, labels, seed, early stopping, and selection; up to 100 head epochs and patience 10. Runtime tuning only changes data-loading and microbatch parameters.

Run on AutoDL from the repository: `python -u tools/run_spatial_ef_readout.py plan`, then `smoke`, then `run`. PLAN and SMOKE do not open TEST labels. Reenter `run` with the same immutable tag to resume an interrupted job. The result, checkpoint, and disposable cache roots are separate. Per-patient absolute-error differences are paired; the bootstrap interval captures patient uncertainty, not uncertainty over independently retrained models.

Decision: a VAL C2-over-C1 gain of at least 0.10 EF percentage points is a practical signal to consider a later FT confirmation. If the two new heads are close and both improve over C0, the shared structural change is a more likely explanation. No material improvement does not show that all spatial information is useless. TEST is descriptive after lock; it is not used to tune or select an arm. This experiment cannot establish any fine-tuning or pretraining gain and does not launch follow-up jobs.

After C1/C2 finish, `python -u tools/evaluate_spatial_ef_c0.py` can supplement the old frozen C0 head with one TEST pass without fitting anything. It checks the original VAL lock, backbone digest and exact C1/C2 TEST windows, and writes the combined report under `control/<tag>/c0_test/` without modifying the sealed C1/C2 outputs.
