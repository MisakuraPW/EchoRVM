## 2. 实验想回答什么

1. 在既定“短clip编码＋向量递归状态＋近期特征缓存”前提下，用更细空间划分建立较强基线。
2. 400轮继续至1600轮，重建、冻结可读性与全量微调是否一起改善？
3. 用同一轨迹的多个节点，区分“训练长度相关变化”和不同学习率日程混比。

本轮不是无记忆/无缓存的架构必要性消融，不是官方EchoCardMAE严格复现，也没有训练A候选。
不以本轮证明递归优于完整视频、临床实时部署或无限长历史建模。

## 3. 模型与数据

| 项目 | 实际设置 |
| --- | --- |
| 数据 | EchoNet-Dynamic，原生112×112灰度缓存，读取时repeat3；无新增RGB磁盘缓存 |
| 单块patch大小 | 8×8像素；空间网格14×14，共196个空间token |
| 旧版对应关系 | patch16像素→7×7网格→49个空间token；不要把patch像素尺寸与网格混用 |
| 局部编码 | 16帧/clip，tubelet2；完整clip有8×196=1568个时空token |
| 当前窗口 | 连续64帧，分成4个局部clip；没有额外历史前缀 |
| 状态 | global向量记忆、mean压缩、fused写入、token端读入 |
| 近期缓存 | 保留4个clip的近期特征；样本之间重置状态 |
| 主干 | 384维、12层、6头；从原始VideoMAE权重初始化，不从旧B0续训 |
| MAE decoder | 192维、4层、3头 |
| 掩码 | tube mask，名义90%；每clip空间可见floor(196×0.1)=19，即152个可见时空token |
| 逐帧读出 | repeat；本轮没有引入可学习tubelet展开等探索模块 |

SSL每轮每个合格视频随机取一个真实窗口，合计10030个视频；短于64帧但足够完整clip的视频按真实clip处理，
不人为补到64帧。固定64病例的重建诊断与训练人口重叠，不是未见人群验证集。

**按用户要求，SSL使用官方TRAIN/VAL/TEST的无标签图像。**
监督阶段只用TRAIN拟合、VAL选权重，未使用TEST标签。这是全split无标签预训练的transductive设置，
不是“整个模型从未见过TEST图像”的严格归纳设置。以后补测也必须披露，不能暗中换成TRAIN-only叙述。

## 4. 训练、选择与自动调优

MAE：1600固定epoch，无早停；AdamW，峰值LR 1e-4，WD 0.05，betas=(0.9,0.95)，
warmup40轮，之后按1600轮完整日程余弦下降。有效batch64，BF16。
从起点按1600轮训练，不是把已跑完400轮余弦的模型继续接1200轮。

每轮覆盖恢复权重，保留0/100/200/400/800/1200/1600快照；每25轮做小型重建诊断。
执行参数自动实测，SSL最终选micro-batch32、workers2、无梯度检查点。
掩码前完整token数不等于encoder实际处理的可见token数，不能只靠196与49预测速度。

监督任务有效batch32，上限100轮，VAL每轮评估，patience10。
冻结探针冻结主干；全量微调开放主干。分割FT为迁移MAE decoder的192维4层头，
前景/背景soft Dice，固定LR 1e-4、WD 1e-4。
EF FT使用近期特征attention读出，末层零权重、bias=.556，百分数L1，固定LR 1e-5、WD 1e-4。
两项FT均使用clip一致的A4超声增强；验证没有随机增强。

## 8. 平均Dice和全局Dice到底是什么

二者都先用argmax得到前景二值mask，再计算硬Dice；都不是训练soft Dice loss。
单次预测Dice为 **2×交集像素数 / (预测前景像素数＋GT前景像素数)**。

**患者平均Dice（dice_mean）**：
先平均同一个真实标注帧在不同目标位置/窗口的Dice，再平均该患者标注帧，最后所有患者等权平均。
它回答“平均一个病例分得怎样”，不会因为某病人的心腔面积大就直接给他更大权重。
本轮仅评估左心室前景一种类，所以dice_class_1与dice_mean相等，不是额外的两种独立成绩。

**全局Dice（dice_global_mean）**：
同一个真实帧的重复位置先平均其交集、预测像素数和GT像素数；
再对所有真实帧累加这些计数，最后算2×总交集/(总预测前景＋总GT前景)。
它不是患者Dice的等权平均，前景面积更大的帧对分母影响更大；同一患者更多标注帧也会贡献更多。
因此它经常与患者平均Dice不同，不能简单称“更准确”，也不能择较高者报告。
本轮只有一个前景类别，因此dice_global_class_1与dice_global_mean相等。

例：患者A的交集90、预测和GT均100，Dice=90%；患者B交集0、预测和GT均10，Dice=0%。
两患者平均Dice=45%，全局Dice=180/220=81.82%。
差异来自加权口径，不是凭空提升性能。

重复位置取的是“各位置Dice平均”和“各位置像素计数平均”，不是先平均概率图再产生一次分割。
空预测且空GT时Dice定义为1；仅一侧为空时为0。本轮官方GT非空，且最终FT没有空预测。
后续论文应同时写清聚合层次、前景类别、有效病例/帧数；与EchoCardMAE比必须对齐其具体实现和split，
不能将本轮VAL患者平均Dice与别人TEST全局Dice直接放一列排名。

## 9. 表征描述不是下游质量证明

128样本描述向量的effective rank从初始13.31升至1600轮67.73，第一主成分占比从30.44%降至9.52%。
这说明描述向量的几何分散度发生变化，不能推出解剖/运动语义更好；冻结任务退步就是需要保留的反证。
终点单样本descriptor提取P50约33.04ms，包含传输和CPU物化、不含视频解码/采集，
不是临床端到端FPS，也不是分割/EF联合持续推理吞吐。

## 10. 为什么没有TEST、如何补而不重训

现有manifest默认只审计TRAIN/VAL，WindowDataset原先将TEST封闭；训练结束后的evaluate仍读exp.val。
队列没有TEST任务，所以根目录DONE只证明已配置的任务完成，不能证明实验科学交付完整。
这是实现缺项，不是没有测试GT，也不是计算不出TEST Dice。

补测入口：`tools/evaluate_patch8_test.py`。它在打开TEST标签前锁定两个VAL best权重及SHA256，
严格加载整个任务模型，复用VAL评估的原生分辨率、窗口、目标位置、指标与执行参数，
不构建optimizer，不更新参数，不用TEST改阈值、选epoch或搜索超参。
默认只测最终全量微调的分割与EF，不为挑好成绩在TEST遍历所有探针和SSL节点。

实例可用后（**尚未执行，不要误读为已有TEST结果**）：

```bash
cd /root/autodl-tmp/EchoRVM
git pull --ff-only
/root/miniconda3/envs/echocardmae/bin/python tools/evaluate_patch8_test.py
```

结果单独进入 `/root/autodl-fs/outputs_cr_spatial/result/cr_patch8_w64_1600_v1_test/`，
不会改写旧VAL汇总或权重。所需最佳权重与SSL权重仍在云端ckpt目录，不必从头预训练。
真实GPU测试耗时尚未实测；这里只做前向推理，不能把过去9分钟/epoch乘100作为补测成本。
该入口本地测试覆盖显式TEST权限、训练/增强拒绝、跨split排除、最佳权重哈希锁定；
原数据流程19项回归及新增2项测试均通过，另通过入口help与语法检查。
真实数据GPU执行仍需补做，不能用CPU测试替代。

TEST图像曾参与SSL但标签未参与，补测必须标记这一暴露范围。
与TRAIN-only SSL论文的严格未见图像TEST结果比较，仍需另立同暴露协议对照，不能靠改报告口径补齐。

## 11. 当前能下的判断与不能下的判断

- 可以：更长预训练确实降低本次重建误差，但不保证固定冻结读出或全量微调同步改善。
- 可以：当前配方的400轮节点值得作为后续开发筛选参考，不必每次默认1600轮。
- 不能：证明400轮对所有设计最优，或直接归因于过拟合、遗忘、递归压缩某一种机制。
- 不能：证明新版超过EchoCardMAE或具有论文标称的TEST性能。
- 不能：用本轮W64、无额外前缀实验证明长视频持续推理的临床收益。
- 不追加：A新预训练、无记忆/无缓存等基础消融；下一步设计由用户确定。
