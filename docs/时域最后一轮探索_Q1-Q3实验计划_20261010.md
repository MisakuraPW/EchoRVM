# 心超 MAE 时域最后一轮探索：问题1—3的实验计划与关闭规则

日期：2026-10-10。

状态：根据用户要求拟定的研究计划，尚未实现本轮新增模块、启动训练或填写协作Excel的核心实验记录。本文的预算、结构和工程判断阈值为计划建议，不替代用户的实验前预测。

## 0. 本轮目的和不可扩张的终点

本轮结束三个问题的设计探索：

1. 近期缓存存在时，RVM采用什么状态、读写和更新方式。
2. Factorized的任务取舍出现在哪里，保留、修改还是不用。
3. 统一骨干的帧级出口能否响应目标帧内容、保留目标解剖，以及历史如何影响它。

随后进入问题4，只确认整体组合并选定唯一时域工作范式，再开展正式训练。问题4的具体组合现在不预设，不能把三个问题分别最好的组件直接拼接为已验证MAIN。

“结束探索”指每个小问题作出可执行的设计决定，并限定没有证实的主张；不要求找到所有现象的唯一因果解释。出现新现象记入局限，不能自动增加模型、rank、clip长度、周期损失或另一轮MAE搜索。

本轮只开发EchoNet-Dynamic；保持L16、112×112、patch8、tubelet2、ViT-S、四clip近期缓存。CAMUS、EchoRisk、频域、其他backbone、密集中间相位标签、全片段位置泛化均不进入队列。测试集继续封存。

## 1. 已核对的事实：计划必须从实际代码出发

### 1.1 当前计算图与张量含义

以完整无mask局部clip为例，P=14×14=196，D=384，G=16/2=8：

```text
当前16帧clip
  -> 局部VideoMAE编码 X_i               [B,8,196,384]
  -> 读取旧状态 S_(i-1) 后融合 Z_i      [B,8,196,384]
  -> 对 X_i 或 Z_i 压缩成写入量 e_i     [B,16,384]
  -> RVM更新 S_i                        [B,16,384]

Z_i -> 基础逐帧展开 H_i                 [B,16,196,384]
    -> factorized（如启用）F_i          [B,16,196,384]
    -> MAE decoder/目标帧分割出口
    -> 空间池化后的有序描述符           [B,16,384]
    -> 最近4个clip FIFO                 [B,最多64,384]
```

实际代码的状态更新在当前重建计算之后调用，但写入量来自展开前的X_i/Z_i；上述图按依赖关系表达，不代表逐行执行顺序。当前decoder还直接读取旧状态。

| 核对项目 | 源码事实 | 对实验的影响 |
|---|---|---|
| 历史接入 | VideoMAE先独立编码，再由`feature_fusion`读旧状态；没有接入每层VideoMAE | 不能把既有结果解释成历史改变了当前clip的原始编码计算 |
| 写入 | `memory_write_source=fused/local`决定压缩Z_i还是X_i | 写入源与读取位置分开控制 |
| 帧模块 | `frame_features`在稠密特征形成后展开；factorized没有直接参与`_pool`和RVM更新 | F训练可能间接改变共享权重，但不存在“F输出直接作为当前state唯一写入源”的既有路径 |
| FIFO | 保存四个clip的逐帧空间均值，最多64个有序384维描述符 | 不是四个整体均值，也不是保留历史稠密token |
| FIFO预训练梯度 | `StreamingFeatureCache`只用于eval/inference，保存detached表示；本身不是MAE训练模块 | 不能宣称近期FIFO作为一个独立模块接受过自监督训练；其描述符来源接受过训练 |
| Dual | 在空间状态之外，保存上一clip池化量，读取时以门控加入旧状态 | 不等于EF末端FIFO；存在额外通路及存储容量差异 |
| `local_empty` | 局部特征保持正常，额外拼接的历史槽置零 | 不是把局部信息清空；旧详细报告这一中文标签有误，后续分析按代码含义修正 |
| 重建梯度 | 帧展开位于像素重建路径；旧状态影响后续clip损失；原生64帧unroll不detach | 存在内容训练梯度，但64帧训练不证明已经学习保留缓存范围以外的真实远期信息 |
| 因果边界 | clip内双向，clip间只用过去；每个clip处理一次 | 50 FPS下最多约0.30秒采集等待；不能称逐帧零等待 |

源码入口：`models/temporal_mae.py`、`models/frame_readout.py`、`models/rvm_core.py`、`models/ef_readout.py`、`utils/streaming_features.py`、`utils/stage3_diagnostics.py`。

### 1.2 Factorized的代数性质必须先用对

令H为基础学习式展开，时间均值为μ，系数映射为A，基底为B。当前实现可写成：

```text
F_t = μ + BA(H_t - μ)
```

这里是逐clip、逐空间patch的参考与变化组织；BA不因存在正交正则就自动成为严格正交投影。对同一组H做均匀时间平均时，mean(F)=mean(H)。因此：

- 不能用“动态项被平均抵消”直接解释两个不同训练checkpoint的EF差异。
- 当前EF头读取有序逐帧描述符，带位置、非线性变换和学习型加权，并非该均匀平均；F仍可能改变它的输入与可读性。
- 同权重下比较H与F，可以定位参数化/读取影响；不同权重C/F之间还包含共享编码器被不同目标改变的影响。

### 2.1 数据人群与上下文

三类固定清单分开保存，所有模型在各清单内匹配病例、原始帧与目标位置：

| 清单 | 用途 | 约束 |
|---|---|---|
| E64-task | 充分冻结与FT校准 | EF真实64帧；分割官方ED/ES描迹对应标签，目标放48—63；train/val患者互斥 |
| E192-history | 状态适配、历史诊断 | 真实128帧前缀+同一近期64帧，不循环、不补假历史；记录FPS/物理时间 |
| E-frame | 内容身份核验 | 与现有dynamic manifest一致的128验证病例优先复用，规范FP32、静态/交换输入 |

对带ED/ES标签的E192目标帧，可能缺少真实128帧前缀。先列可用患者数；不足64名配对验证患者时，不把少数长视频主导的结果升为主结论，也不制造假前缀。问题3仍使用E64中的局部/融合出口回答既定范围内的历史影响。

验证集已经被反复用于开发，本轮结论按开发选择报告。所有bootstrap先按患者聚合，不能把16位置、多个标签或干预视图当独立患者。

### 2.2 一次性任务校准A：旧P/C/F的共同读出

这是必做的6个充分冻结训练+6个完整下游训练，贯穿问题1—3并留给问题4复用。若不存在可核验的同协议既有结果，就不能跳过。

| 类型 | EF | 分割 |
|---|---|---|
| 冻结训练 | P/C/F各1次，共同`TemporalEFReadout`，hidden64，有序近期描述符 | P/C/F各1次，共同ViT patch decoder，dim192/depth4；每个模型一个共享头 |
| 全量微调 | P/C/F各1次，使用相同头结构 | P/C/F各1次，使用相同decoder与位置采样 |
| 输入 | 真实近期64帧；窗口内RVM照常更新，额外历史为空 | 真实64帧与官方目标帧，48—63均衡覆盖 |

EF额外显式历史槽的数量/类型在模型间一致；主校准不把192帧长视频子集当整个下游人群。分割不添加独立单帧encoder；EF不保存全视频稠密token。两个任务的FT各自形成两套下游权重，但起点为同一预训练checkpoint。

统一预算建议在实施前登记：冻结头最多60个完整epoch、patience12；FT沿现有80 epoch上限、patience20。最佳权重按val EF MAE/患者Dice选择；不能按train高分选点。EF、分割分别用同一预先固定配方，不逐模型调学习率或head容量。冻结头和FT都保存训练曲线；达到上限仍下降则如实称“本适配预算下结果”，不为某一模型单独延长。

首次实施使用以下共同配置，若一次盲于模型分数的稳定性冒烟发现NaN等数值问题，只统一修改对应任务配方后锁定，不按P/C/F分别调参：

| 参数 | 冻结EF | 冻结分割 | FT EF | FT分割 |
|---|---|---|---|---|
| 优化器 | AdamW | AdamW | AdamW | AdamW |
| 学习率 | 1e-3 | 3e-4 | 5e-5 | 1e-4 |
| weight decay | 0.01 | 0.01 | 1e-4 | 1e-4 |
| loss | SmoothL1，训练集EF目标归一化 | CE+Dice（权重1:1） | 与冻结EF同一输出/目标单位 | 与冻结分割相同 |
| 梯度裁剪 | 1.0 | 1.0 | 1.0 | 1.0 |
| warm-up/调度 | 3epoch+cosine | 3epoch+cosine | 5epoch+cosine | 5epoch+cosine |
| 上限/早停 | 60/patience12 | 60/patience12 | 80/patience20 | 80/patience20 |

EF特征/目标归一化只在训练集拟合，不把旧probe的标准化回归与FT的sigmoid百分比输出直接混用。FT切换参数可训练状态，不切换head定义；各模型head初始化种子一致。冻结分割不沿用770参数小头的0.01学习率直接训练大decoder。

冻结训练为高效特征缓存协议，不做随机在线增强；FT统一沿现有A4增强，视频内参数一致，zoom同步作用image/mask，val不增强。因此冻结与FT的变化反映适配协议整体差异，不能被简化成只由解冻编码器导致。各类型内三模型严格一致。

特征缓存每次只保留一个checkpoint的任务特征。EF缓存有序描述符；分割每个源标签预先分配均衡的训练位置，val各位置流式读出，不持久保存全部患者×16位置的稠密特征。训练数据量不靠扩大小头步数伪装。

FT更新所有参与该任务前向的共享编码器、帧模块、RVM、融合/压缩和任务头；unused MAE decoder不在任务优化器中。这是完整任务主干微调。实现时按实际参数对象检查冻结和梯度，而非只依赖参数名前缀。

### 2.3 主指标与选型尺度

主指标为EF MAE（百分点）、患者平均Dice（百分点），分别报告，另附RMSE、患者Dice的P10、16位置均值/极差和计算成本。边界误差只在Dice与边界现象明显矛盾时，对已生成预测补一次计算，不为它另训模型。

建议在新结果前固定工程参考尺度：EF可关注0.3 pp变化、Dice可关注0.5个百分点变化；它们不是临床非劣界限，也不是用户已经锁定的预测。bootstrap区间用于表达不确定性，不以是否跨零作自动否决或自动等效判断。

新增方案进入下一阶段的建议条件：至少一项主要迁移指标有超过上述尺度的正向变化，另一项代价没有明显超出该尺度；或在任务接近时清楚降低成本/改善已登记接口缺陷。接近、不稳定或无法区分时选现有更简单的实现，不追加实验“测到显著”。

所有新MAE适配仅用一个预训练种子42。最多给入选方案与参照补一套读出种子43，固定同一患者清单，只改head初始化/训练采样；它不是第二个MAE种子。正式多MAE种子确认留给之后正式训练。

## 3. 共享机制队列B：有限适配，统一起点与预算

### 3.1 为什么采用共同C起点

当前C已同时具有时间感知压缩和学习式帧展开，是多个信息流问题的共同参照。队列B全部从同一C的100轮checkpoint出发；新模块共享参数按同一种子载入，优化器重新初始化，不称完整optimizer resume。

现有F100仅作校准和同权重诊断；归因比较中的新factorized必须从同一C起点适配，不能把F已有100轮特殊训练与C短适配混为一个单因素比较。

队列B每个配置固定1500个optimizer更新，有效batch32，lr1e-4、AdamW、无增强/早停，192真实帧=12个L16 clip。只对最后64帧计算同一masked重建目标；前128帧编码、写状态并完整保留梯度。前缀decoder可以跳过，但不能no_grad/detach前缀后声称训练了缓存外历史写入。

这改变了训练上下文和损失范围，所以必须有B0同预算继续训练参照。它是给定已训练起点的联合适配，不是从VideoMAE初始权重重训至同等上限。

| ID | 配置 | 改动/用途 | 对照 |
|---|---|---|---|
| B0 | C-continue | spatial16槽、temporal_attention、融合写入、展开前读取；共同适配参照 | 原C100只作前后描述 |
| B1 | C-dual | 空间state之外保留上一clip短期通路 | B0 |
| B2 | C-local-write | 只将压缩写入源从Z_i改X_i | B0 |
| B3 | C-late-read | 在B2基础上，memory读取从基础帧展开前移到展开后共享出口 | B2 |
| B4 | C-lowrank-candidate | 仅将RVM规范化candidate沿通道轴作rank32可学习瓶颈 | B0 |
| B5 | C-factorized | C起点启用现有rank16帧参考—动态机制与既有正交项 | B0 |
| B6 | C-shrink | 共享参考+全维变化收缩，无低秩瓶颈 | B0/B5 |
| B7（条件） | C-soft-factorized | 唯一允许的结构修正候选，固定β=0.5 | B0/B5/B6 |

必做7个配置，其中B0是必要控制；B7最多一次并按第5节触发。没有global/rank/投影/门控/压缩器的额外网格。

每配置训练结束只做一次充分冻结EF/分割终点。B0—B6共14个主终点head；分支/历史对比复用提取特征，不新增MAE。预算与共同头按A登记；历史小人群诊断单独列，不混进E64主任务表。

训练上下文192、近期缓存64、局部clip16必须是三个独立配置。当前工具有按`model.frames/local_frames`推导FIFO容量的行为，本轮不能让192训练上下文把FIFO意外变成12段。推理固定capacity4，任务64帧前向通过合法stream接口实现。

### 3.2 两个新机制的精确定义

**B3晚读取。** X_i不读state；B2/B3都压缩X_i写状态。先由同一基础learned展开得到H_i，再用D=384共享`CrossBlock(H_i,S_(i-1))`形成J_i；J_i接入MAE decoder并作为帧级出口/近期描述符来源。旧decoder的直接memory路径在B2/B3中保持一致。只移动特征读取的位置，不同时改写入源或加新encoder。因learned展开存在两个offset投影，这个移位通常不是repeat情况下简单重复token的等价变换；实施前仍用输出/梯度确认不是纯代数重复。

**B4低秩candidate。** 当前RVM为：

```text
z = sigmoid(Wx e + Ws S)
r = sigmoid(Rx e + Rs S)
candidate = LN(integration(e, r * S))
S_new = (1-z)*S + z*candidate
```

只把candidate替换为`B_s A_s candidate`，通道rank固定32、所有16空间槽共享基底；门控、空间槽、读取和写入源不变。初始化可由训练集candidate统计的PCA/SVD确定，不用验证集选rank。经过逐元素门控后，最终state不一定低秩；名称固定为“低秩候选写入”，不能写成低秩总memory，也不预设降低state存储。

**B6变化收缩。** `Y=μ+γ⊙(H-μ)`，γ为384维共享学习量，初始化1。使用与B5相同参考、可见token和clip边界，保留全维变化，用于检验是否只需要参考/收缩，而不一定需要选择性低秩子空间。

## 4. 问题一：缓存存在时RVM如何工作

### Q1.1 状态对缓存外历史究竟有什么价值？

**实验。** 先复用旧H0/H128/重复前缀证据；对B0与入选memory候选做一次E192匹配读出。近期64帧完全相同，三个条件：H0（没有额外前缀）、H128（真实128帧）、HR（等长重复前缀）。H0仍保留近期4段内的RVM，不能称none。先分别训练同容量head评可达到的读出，再用H128训练好的固定head作移除/替换依赖诊断。

同时读取局部描述符L、历史融合描述符Z，以及缓存开始前的边界state；显式槽真/零的比较保持同一局部或融合缓存。这项输出也供Q3.3使用。

| 观察 | 支持什么 | 设计决定 |
|---|---|---|
| H128优于H0且HR，合法局部+边界state也有改善 | 固定缓存外真实历史有内容相关的边际价值 | 保留旧state及明确history接口 |
| H128与HR接近，但二者优于H0 | 可能有warm-up/表示分布适配效应，远期运动贡献未区分 | 保留工程状态，删除“已证明更早运动语义”的主张 |
| 固定头对移除state敏感，但分别训练head后接近 | 读出依赖/分布改变，不等于不可替代信息 | 不用干预掉分单独当创新依据 |
| H128无净益甚至干扰 | 当前任务下额外远期历史收益未支持 | MAIN候选允许有界state保留接口，但是否进入任务出口由后续整体结果决定 |

**关闭。** 固定“近期缓存以外的历史适用范围、是否进入输出、可声称什么”；不再尝试H256/H512、重复次数、长期状态可线性预测EF的网格。

### Q1.2 状态应该怎样组织，dual是否还值得保留？

**实验。** B0 spatial与B1 dual同起点/同适配/同任务头。已有global/none/旧spatial/dual结果仅作背景，不把不同轮数排名并入本轮主对照。

**判断。** Dual若给主要任务稳定净益且另一任务代价可接受，保留其上一clip通路；若与spatial接近、额外存储/复杂度增加，则固定spatial。Dual若仅改善某个依赖干预但正常任务无益，不采用。

**关闭。** 选择spatial或dual作为问题1的条件性工作状态。它是完整配置比较，包含容量/通路差异；不宣称纯空间组织的因果优势，不补同容量无空间槽族。Global没有新的强证据触发，不重开。

### Q1.3 历史在局部表示形成前后何时读取，写什么？

**实验。** B0-B2只改写入源；B2-B3只改读取位置。用正常输入下的EF与目标帧分割判断，附局部/最终出口的配对可读性。共享源帧/病例/缓存长度，不用“把state直接插进另一个checkpoint”替代适配。

| 观察 | 可以回答 | 固定方式 |
|---|---|---|
| B2优于B0 | 当前反馈写入方案可能不如独立局部写入 | 使用local写入；结论针对本背景 |
| B0优于或接近B2 | 历史融合写入没有出现值得更改的净代价 | 保留融合写入 |
| B3空间信息更好且EF代价可接受 | 先形成局部帧表示、再由历史条件化出口更合适 | 选晚读取/local写入完整配置 |
| B2更好或B3无优势 | 移动读取没有带来可用收益 | 维持展开前读state |
| 分割与EF方向冲突且无法消除 | 读取作用依任务而异 | 选择较稳健完整配置，记录允许的粒度出口，问题4再确认组合 |

**关闭。** 明确选中的read/write位置与缓存来源；不扩展VideoMAE逐层注入、不同attention层位、门公式和衰减率搜索。所有结果都标注“given C/当前展开条件”，不能先宣布与任何frame模块都兼容。

### Q1.4 现有更新是否异常，低秩候选写入有没有必要？

**实验。** 对训练mask及unmasked推理各抽取预先固定32个训练窗口，记录update/reset分位数、candidate/state/update范数、饱和比例，确认最后64帧loss对前128帧encoder和更新参数有非零有限梯度。统计是描述，不用门均值解释“用了多少百分比历史”。

B4与B0比较最终任务、状态稳定性、成本；可附真实/重复历史响应。没有增加周期闭环loss、state与心率对齐或静态PCA美观度作为成败门槛。

**判断。** 低秩candidate有净迁移收益或明显稳定性/成本收益才进入下一阶段；若任务下降、rank限制不足、仅轨迹变漂亮、或预算内接近，就不用。若发现NaN、mask泄漏、state不受内容训练等技术错误，修复并重跑受影响对照；不是自动更换rank/加新网络。

**关闭。** 对rank32这一具体作用位置作采用/不采用/预算内未确认的决定。未确认按原更新收敛，不再扫描rank或整state低秩。

### 问题一结束时的回答

交付唯一**条件性memory规范**：state形状、dual开关、压缩器、写入源、读取位置、门控/低秩开关、重置边界、缓存外历史范围与证据。选择以正常下游任务为主，保留流式需求；不要求RVM在每个离线分数都击败none，也不把无独立收益写成已经证明的远期语义。

## 5. 问题二：Factorized的代价在哪里，如何收敛机制

### Q2.1 EF下降是真实适配代价还是旧小头低估？

**实验。** 首先看A中P/C/F的充分冻结与FT。相同任务头容量、相同输入、同一预算；不要只给F增加head容量或训练轮数。

| 冻结/FT结果 | 能作的结论 | 后续处理 |
|---|---|---|
| 充分冻结恢复F的EF，分割优势保留 | 原400步probe不足可能参与旧取舍 | 不为旧表格强行改F结构，仍看共享出口诊断 |
| 冻结差、FT恢复EF并保留分割 | 表征可读性与有限任务适配性能不同 | F可以作为可适配结构，不能称冻结表示本来没损失 |
| 冻结与FT都保持EF损失 | 存在本预算内稳定的任务代价 | 定位接口，必要时触发唯一修正 |
| 更充分训练后分割优势也消失 | 旧小probe正向不稳定 | 不强留F，只完成有限归因后作不采用决定 |

**关闭。** 决定当前F的取舍是否仍成立；不能用“一定微调能救回来”或“容量有限必然取舍”作未经实验的答案。

### Q2.2 代价出现在哪个环节？

**实验。** 在同一C/Fcheckpoint中提取三个可用出口，不做全层穷举：

1. `local_base`：X_i经基础learned展开，空间池化成有序描述符。
2. `fused_base`：Z_i经同一基础展开；F模型取其`frame_expansion.base`输出。
3. `fused_final`：最终frame输出，C等于基础展开，F含参考/低秩变化。

每个出口使用同容量EF头与训练集拟合归一化，配对病例固定；对应帧网格作分割读出。已有`frame_features(local_features)`在F中仍会经过factorized，不能把它误叫factorized前出口。

| 模式 | 最可能定位 | 决定/主张边界 |
|---|---|---|
| F的base好、final差 | 参数化/出口和有序汇聚适配有关 | 优先选择合法base EF出口；不称不可逆丢光信息 |
| F的local_base好、fused_base差 | 历史读取/融合相关 | 用问题1同批对照解释；不重复增加另一套state实验 |
| F所有base出口都比C弱 | 训练影响已传播到共享编码器或更早路径 | 保留训练层影响解释，不认定纯容量上限 |
| 均匀池化同权重H/F近似相同，但attention读出不同 | 支持差异与动态/有序读取有关 | 不用均值抵消等式解释跨checkpoint差异 |

合法的EF base出口来自同一次前向，并通过F的内容重建接收预训练梯度。它不会取消RVM，不增加第二个encoder，也不保存全历史稠密token。出口诊断若恢复性能，是可能无需新结构的设计决定；正式整体组合仍需问题4确认。

**关闭。** 将最可能瓶颈定位到共享训练、历史融合、帧参数化或当前读出适配中的一处/有限几处；仍无法唯一定位时保留多个解释，并固定已验证出口。不再逐层追踪encoder或为追求唯一原因追加网络。

### Q2.3 收益更像参考/收缩，还是选择性低秩？

**实验。** 同一C100起点、相同1500更新和192/64训练协议比较B0、B5、B6。现有F100作外部历史参照，不能当B5等起点替代。

**判断。** B6接近或超过B5，则优先将发现表述为参考—变化组织/收缩的价值，可选更简单B6。B5超过B6，且EF取舍可接受，才有更强依据保留选择性低秩机制。B5/B6都无净益，则原普通展开收敛，不为“创新名称”保留复杂度。

16帧单clip中心化时间矩阵自身秩最多15；rank16机制约束的是跨clip/病例共享的通道变化子空间，不能用某个单clip的低秩PCA图证明该机制有效。因此这项比较以迁移读出和同起点控制为依据。

正交正则做一次内容梯度/正则梯度的量级及方向记录；小loss值不等于无作用。本轮不单独主张正交正则贡献，因此不另开去正交训练。若它参与最终结构，贡献名写“完整参考—动态参数化”，将正交作用单独未隔离作为明确边界。

**关闭。** 确定需要的是低秩、全维收缩还是普通展开。未做完全因素分解不阻止设计收敛，但不能写成低秩/正交的唯一因果贡献。

### Q2.4 是否改结构：只允许一次已登记修正

优先使用Q2.2已经存在且受预训练的合法出口解决读取问题，不添加新任务encoder。

只有同时满足以下条件才跑B7：A中F仍保留实质分割/帧身份收益；EF在足够适配或三个合理出口后仍有不可接受代价；B5/B6表明硬限制动态变化是较有依据的解释。若读出换base已经足够，或F收益消失，B7跳过。

B7固定：`Yβ=H+β(F-H)`，β=0.5，不搜索β、不同时试共享矩阵投影、query、额外周期损失。它从C100开始同样1500更新，使全维残差非排他保留；与B0/B5/B6同预算。不能从B5再多训1500后归因于soft机制。

B7若恢复EF且保留空间收益，选择soft候选；若仍有明显代价，选择普通展开或B6。运行B7后不触发B8。

**关闭。** B7跳过、成功或失败均产生一个frame机制决定；后续只把该候选带入问题4，不再围绕F开结构补救轮次。

### 问题二结束时的回答

交付：既有F的充分冻结/FT取舍；最可能作用位置；普通、hard factorized、shrink或soft中**一个条件性frame方案**；EF与分割各自允许读的同次前向出口；可以写成贡献的事实与必须降低的解释主张。不得以仍有不确定性为由重开frame结构设计。

## 6. 问题三：内容身份、目标解剖和历史互补

### Q3.1 相邻两帧出口是否响应内容，而不仅是offset模板？

**实验。** 复用repeat/learned/F的现有128病例轨迹与交换诊断，并在固定病例上一次性补可靠精度核验：真实相邻帧、同帧重复、tubelet内交换。保持相同offset，FP32读出；报告配对准确率、tie、正确/交换MSE差的标准化margin分布，而不只报accuracy。

内容读出在训练病例拟合；验证不翻转正负、调阈值。低变化帧对排除规则只由训练集图像差异登记，报告保留/排除数量。静态offset模板单列；不要求真实相近帧距离很大。

**判断。** 相比repeat基线，真实内容变化带来一致匹配margin、交换响应，且不由静态offset差解释，支持“内容可区分”。只有非零特征距离或静态两offset不同，则仅支持位置可区分。FP32核验推翻旧信号时降低身份主张，但仍按真实解剖读出选择方案，不新增帧间排斥训练任务。

**关闭。** 使用已有模块或问题2入选模块，不因此再造新frame网络。ED/ES命中、PCA、recurrence沿用为辅助描述，不设医学运动空间成功门槛、不为其新训练。

### Q3.2 是否保留目标帧的解剖？

**实验。** 主证据直接复用A及B终点共享分割头。目标是同一官方源标注帧，放在48—63的匹配位置；主表为完整上下文患者Dice，附每位置均值、P10和低分病例例图。例图采用固定病例/按预登记分位抽样，不能只挑漂亮结果。

**判断。** 内容身份提升且目标Dice提升/可接受，支持可用于目标帧空间读出；身份提升但Dice下降，则不把纹理识别当解剖保留。充分头恢复位置稳定性，说明旧位置覆盖/头适配参与现象；仍不推导全部未标注临床中间帧精度。

**关闭。** 固定一个frame grid出口与其target/source索引语义。不新增全片段位置或密集相位GT研究。warm-up患者保留独立统计/功能边界，不伪造完整过去上下文混进主表。

### Q3.3 历史到底补充还是干扰目标帧？

**实验。** 直接复用Q1同一模型的local/fused/late出口、H0/H128/HR（真实前缀标签可用时），以及相同目标源帧。共同头分别训练的能力比较与固定头干预分开报告。

**判断。** 正常合法输入中，历史融合出口在目标解剖上有净益，支持当前协议的时间互补；无益或变差，说明输出应弱化/晚读历史或用局部frame出口，而不否定所有时域任务。真实与重复前缀接近，则不把改善全写成长期内容。前缀标注人群不足时，历史边际主张限定在E64已有上下文。

**关闭。** 选择局部、融合或晚读取的合法frame出口，并说明历史覆盖。完全共用Q1特征，不另开“分割时序模型队列”。

### Q3.4 新出口是否保持合法流式与有限存储？

**实验。** 对最终最多两个候选和参照，复用既有真实512帧脚本；增加的是新路径检查，病例不另扩。验证新clip只更新一次、读取不更新state、目标源帧身份、patient reset、断帧拒绝、FIFO固定四段、与合法离线顺序前向一致。首clip/未满四clip明确warm-up，禁止复制数据补过去。

模型计算、H2D、任务头与采集等待分开测；记录真实FPS。没有读取未来clip；factorized参考仅在已到达且完整的当前clip计算。在MAE中参考只由可见token形成，隐藏位置只用于loss。

**关闭。** 形成可执行的流式出口规范及已测等待/存储边界。通过有限检查不宣称临床部署完成；未验证外部设备与小时级视频写入局限，不开启另一个部署研究轮次。

### 问题三结束时的回答

交付同一骨干的frame/video出口表、内容身份的证据等级、ED/ES解剖可读性、48—63位置适用范围、历史影响、warm-up与持久状态边界。该问题可以只产生能力规范，无需强行创造一个独立网络创新点。

## 7. 执行顺序、计数和成本约束

### 7.1 固定队列

1. 登记科学协议、真实checkpoint与计算图；一次诊断可见mask/梯度/帧索引。只修影响有效性的实现错误。
2. A：P/C/F各做EF、分割充分冻结和FT，回答旧小头是否低估；完成已有F的三个出口定位。
3. B0—B6共同C起点适配1500更新，各一次冻结任务终点；Q1/Q2/Q3共享病例与特征。
4. 如且仅如Q2.4条件满足，B7跑一次。
5. 给参照与一个最有必要的入选适配候选最多补两个任务的FT确认（2模型×2任务=4次）。这四次是全队列共用额度，不给每个memory/frame分支分别补四次。若旧F经A已经足够、无需新修正，则额度用于问题1最关键的状态候选。其他条件性选择以充分冻结/机制证据收敛，完整组合留给问题4。
6. 对上述入选对照最多做一套head seed43确认，病例保持相同。完成三份问题结论表，关闭Q1—Q3，进入Q4。

### 7.2 硬数量上限

| 工作 | 必做 | 条件上限 | 说明 |
|---|---:|---:|---|
| 历史P/C/F充分冻结任务训练 | 6 | 0 | EF/分割各3；无新MAE |
| 历史P/C/F全量微调 | 6 | 0 | 同一checkpoint分别适配两个任务 |
| 新MAE联合适配配置 | 7 | +1 | 含B0参照；总更新最多12,000，不是8组新100/400轮 |
| 新配置主冻结终点 | 14 | +2 | 每配置EF/分割各1；历史/出口读出复用提取，不增加MAE |
| 入选适配模型FT确认 | 0 | 最多4 | 全队列额度，不按每个问题累乘 |
| 多出口/历史/身份诊断 | 固定同批数据 | 不增加网络 | 三出口，H0/H128/HR，FP32身份核验 |
| 第二head种子 | 0 | 入选对照1套 | 不当成MAE重复、不重复采样更多队列 |

“任务head训练”与“新增MAE结构”分别计数；它们的GPU成本相差很大，不能把每个CSV条件算成一组新MAE。但本计划也不应宣传成几分钟完成：六个完整下游微调是新的主要成本。

### 7.3 开跑前的时间预算方式

本地记录可确定：此前L16的新100轮完整训练约2—4小时，combined约4小时51分钟墙钟含恢复/调参；本轮192上下文、末64loss及大head与旧协议不同，不能直接用81分钟或旧小头评估几十秒估算全队列。

实施时在服务器对代表性MAE、冻结head、完整EF、完整分割各做一次真实成功更新测时，预热后记录20个optimizer更新与一次val的中位时间。冻结head用缓存吞吐估计；FT按病例数、有效batch、epoch上限计算：

```text
阶段上限耗时 = 预定更新数 × 中位每optimizer更新时间
             + 预定验证次数 × 验证时间
             + autotune/保存/提取时间
```

在第一次正式训练前给出必做/最坏分支GPU小时并锁定`budget.json`。若预算过高，优先取消四次可选FT和第二head种子，再在看新分数前等比例缩减所有B适配更新（下限750）；不能删去B0或只给弱模型减预算。本计划不虚构未测的固定GPU天数，数量上限本轮不会扩大。

## 8. 工程要求与一次性有效性检查

- 自动调优只调micro-batch、worker、prefetch和执行策略；保持有效batch与成功optimizer更新数。所有比较使用相同checkpointing/精度策略；从实际启动日志核对，不能只看autotune建议。允许micro-batch因显存不同，但记录mask分组/浮点执行差异。
- 1500更新按成功optimizer.step计数，AMP跳步不前进scheduler或计入预算。长前缀完整BPTT先用B=1验证；OOM优先重计算/减micro-batch、增累积，不能静默detach前缀。
- 现有默认FT YAML的32/8帧等老设置不能直接用于本轮TemporalMAE。配置必须由checkpoint合同与本轮64/192上下文生成；尤其当前Stage2 EF的`cache`模式会从近期窗口开始而跳过prefix，不能把它当H128历史模型。
- MAE无label；supervised head训练与FT按各自定义记录。冻结时真正冻结所有共享参数，head可以训练；train/val患者交集必须为0。
- 只用输入可见token算参考、压缩和state；隐藏图像不能经mean/reference流回encoder。诊断一次内容重建梯度确实到帧模块、旧状态与新低秩模块。
- 一次对齐`train/eval`、源帧索引、H0/HR/H128、uniform-mean等式、target offset与合法stream结果。遇到技术bug只重做受影响实验；科学差异或不确定性不触发修复式无限重训。
- 结果、权重和大特征缓存分离：`outputs_temporal_final/result/RUN_TAG/...`、`ckpt/RUN_TAG/...`、`cache/RUN_TAG/...`。每个新MAE只保留滚动last完整恢复状态和final轻权重；每300成功更新覆盖last，不存密集阶段快照。
- 任务训练只保留last恢复与best权重，不留每5epoch大网格快照。缓存按一个checkpoint处理，完成即删除本轮缓存；不清理旧项目数据/权重。预留至少5GB，启动前按权重/缓存大小估算，磁盘不足明确停止保存/任务，不能假装完成。

## 9. 三个问题的最终结论模板与进入问题4的门槛

每个小问题必须填写以下五项，缺失则不能标记该项关闭：

1. 对照与实际运行预算，数据/源帧/参数是否匹配。
2. 主要观察、效应大小、患者区间和种子范围。
3. 支持的解释与仍不能区分的替代解释。
4. 具体采用/不采用/保持参照的设计决定。
5. 关闭声明：未解释现象记入论文边界，不再自动加实验。

| 大问题 | 必须落地的答案 | 可接受的保守答案 |
|---|---|---|
| Q1 | 一种条件性状态组织、read/write/update、FIFO和历史适用范围 | 维持spatial、原更新；真实缓存外收益不明确则不主张医学远期语义 |
| Q2 | 一种条件性帧机制与EF/seg合法出口、取舍定位 | 不使用factorized，或保留参考—变化组织但不主张低秩/正交单独贡献 |
| Q3 | 统一骨干frame/video接口、内容/解剖证据与流式边界 | 保留任务可读出口，身份/未标注帧能力只按实测范围表述 |

只有这三份条件性规范、实际checkpoint和证据齐全，才设计问题4。届时最多选一个现有稳健参照和一个依据结果形成的整合候选；联合适配后选择一个MAIN。不得拼装不同模型的最好分数、混装独立权重或把未验证出口临时塞进最终模型。

无论Q1—Q3出现正向、负向或预算内无法区分的结果，都进入问题4。没有充分医学解释时删除解释主张，没净益时不保留组件，接近时回到更简单参照。问题4结束后正式训练按唯一范式展开，时域设计探索不再自动回流。
