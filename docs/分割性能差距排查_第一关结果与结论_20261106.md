# 分割性能差距排查：第一关结果与结论

日期：2026-11-06。实验代码版本：`b966c64`。本轮无新增MAE预训练。

## 1. 最重要的结论

**现在已有一条不必重新预训练、也不必更换递归架构，就能在完整EchoNet分割TEST上达到约93%全局Dice的干净基线路径。**

- 我们的patch8、独立400轮SSL权重，恢复分割监督覆盖并按VAL选出的模型：TEST全局Dice **93.0135%**，患者平均Dice **92.4633%**。
- 本轮官方发布权重的单帧实现锚点：相同1276个有标注病例、相同2552个真实标注帧，TEST全局Dice **92.9765%**，患者平均Dice **92.3920%**。
- 两者全局差 **+0.0370个百分点**，患者平均差 **+0.0712个百分点**。应解释为**本次运行的成绩接近**，不是证明我们的MAE超越EchoCardMAE，也不是多种子等效性结论。
- 原独立400轮权重不变，分割头、学习率、优化器、有效batch、增强与选择规则不变，修复监督覆盖后，在原共同VAL上也确有改善。因此，不应再把先前分数偏低直接归结为“递归架构不行”或“需要先加ROI/对比学习才可能接近93”。
- **这不等于完全排除了架构和训练参数的影响。** 本轮解决的是“当前基线能否达到接近官方的实际水平”和“监督实现是否确实拖累了它”，不是把所有科学因素逐一做完因果分解。

处理决定：这轮排查到此收尾。保留patch8、校准后的头、完整可用分割监督与明确边界处理，作为下一阶段开发参考；没有自动启动mask/ROI/A训练，没有新增400/1600轮MAE，没有为了追分继续调TEST。

## 3. 为什么原先监督不完整，这次怎么修复

原分割数据集要求目标帧满足完整64帧上下文及16种目标位置的可取性。这对机制探索方便，但把上下文完整性变成了使用GT的前提，丢掉了大量真实标注帧。

| 项目 | 原限制版本 | 恢复监督版本 |
| --- | ---: | ---: |
| TRAIN有分割监督的病例 | 4975 | 7460 |
| TRAIN真实可用标注帧 | 8108 | 14920 |
| 每次验证前的训练抽样数 | 8108 | 8108 |
| 有效batch | 32 | 32 |
| 每个virtual round优化更新数 | 254 | 254 |
| 用于选权重的VAL病例/源帧 | 902 / 1478 | 902 / 1478 |
| 选权重VAL观察数 | 23648 | 23648 |

实际恢复了 **6812个TRAIN标注帧**。原监督只占当前完整可用标注帧的约54.34%。以前按旧候选池得到的6736个丢帧数，不是这次完整manifest的恢复总数，应以本次14920与8108为准。

FileList中TRAIN为7465个视频，但其中5个没有可用的分割trace，不能虚构GT；完整可用监督因此是7460病例、14920帧。该5例也有尺寸元数据异常，manifest保留了这两类事实；不能仅凭二者重合便认定没有GT是尺寸处理造成的。VAL有1288病例/2576帧；TEST的FileList为1277例，实际有分割标注1276例/2552帧。两种新模型使用相同的真实标注人口。

修复规则：

- 旧有可用帧仍走原取窗/目标位置/增强逻辑，保持共同VAL与旧流程可比。
- 新恢复帧用截至该目标帧的16/32/48/64帧短上下文；不足一个clip时只在左侧复制该视频首帧，并记录补帧量。
- GT仍然是原真实目标帧，不给复制帧伪造监督。
- 完整训练池连续确定性随机排列、跨virtual round游走，一轮排列耗尽前不重复抽样。不是每轮固定只用同一半标注。
- 共同VAL仍按16个合法目标位置评估；完整VAL与TEST的新增边界帧各用一次可用短上下文。

重要边界：**只有新增边界样本使用上述因果短上下文；旧样本保留原目标位置逻辑。这轮并没有证明全部评估都是严格实时因果推理。** 共同源帧的多位置分数是重复上下文评估平均，不是把多个mask融合后再算Dice，也不是全部只看单帧。

## 4. 指标口径：不要再把两种Dice混为一谈

- `dice_mean` / `dice_class_1`：同一标注源帧先平均它的多个窗口/位置Dice，再在患者内平均，最后等权平均患者。这里是单前景类，所以两字段相等。
- `dice_global_mean` / `dice_global_class_1`：同一源帧的重复位置先平均交集/预测像素/GT像素计数，每个源帧只贡献一次，最后算`2*总交集/(总预测像素+总GT像素)`。单前景类下两字段相等。
- EchoCardMAE原EchoNet代码的前景Dice采用全局混淆矩阵聚合口径。因此，讨论其约93%的分割水平时，应该优先对齐我们的**全局Dice**，同时保留患者平均Dice。
- 患者平均和全局Dice回答的权重问题不同，后者并不天然更好；本轮恢复监督TEST为92.4633%与93.0135%，这0.5502个百分点不是模型变化，而是聚合方式不同。
- ASSD、HD95是原生112坐标下的像素距离，不是毫米。本轮分割结果没有空预测/边界失败；一般情况下有效边界距离不能代替所有病例分数。

| 指标 | 原监督FT | 恢复监督FT | 改变 |

| 全局Dice | 92.5138% | 92.7382% | +0.2244个百分点 |
| ASSD | 1.1612 px | 1.1319 px | -0.0293 px |
| HD95 | 2.8530 px | 2.7588 px | -0.0943 px |

患者配对bootstrap，2000次、seed42：患者平均Dice差为+0.3606个百分点，95%区间约[+0.2451,+0.4774]个百分点。它只是本次固定模型的患者采样不确定性，不是独立训练随机种子的置信区间；也不是用区间是否跨零决定下一步的门槛。

不能忽略的混杂：每个检查周期更新预算相同，但最终恢复监督训练了49轮，原版本16轮；最佳权重分别位于39与6轮，累计更新不同。此外，新标注需要新的边界上下文，实际micro-batch也由运行器选定。因此不能把+0.3606全部命名为“单独增加数据量的因果收益”。

为检查是否仅仅多跑了33轮，本地只用已保存VAL历史做了等16个检查周期的描述性截断：原最佳91.8759%，恢复监督前16轮按同样min_delta规则选中第11轮92.0275%，仍有+0.1516个百分点；对应全局92.5138%→92.6627%。没有重新加载该中期权重测TEST，也没有按这个事后观察替换既定终点。

这支持“修复监督覆盖与必要边界处理是有价值的实现修复”，但仍不等于无随机性、无优化轨迹影响的纯单因素证明。

## 9. 性能差异到底查清到哪一步

| 解释 | 本轮证据与结论 | 是否已完全隔离 |
| --- | --- | --- |
| 错把患者均值和官方全局Dice比较 | 已确认会夸大表面差距；两口径已同时提供 | 指标定义明确，但不能用口径变化冒充训练提升 |
| 旧分割监督被上下文规则砍掉 | 8108→14920帧；同源、同共同VAL改善；完整TEST接近锚点 | 恢复覆盖+边界处理+优化轨迹的组合有效，不是纯数据量因果结论 |
| 通用分割流程无法得到官方水平 | 官方权重锚点TEST92.9765%，与既有约93可靠记录接近 | 不支持有大幅通用流程退化；不等于所有实现绝无bug |
| patch16太粗 | 早已改patch8；当前是112/8=14×14=196空间token/帧 | 本轮未重跑patch16，不能单独量化其贡献 |
| 下游头过轻 | 本轮沿用已校准192维×4层decoder transfer头，没有再换 | 头已不是旧轻头；本轮非头消融 |
| 递归架构天然导致远差于官方 | 当前递归基线完整TEST已接近官方锚点，实际大差距前提不成立 | 未证明架构无影响或有优势 |
| 掩码、ROI、对比学习、预训练配方差异 | 没加这些也得到约93全局Dice | 说明不是达到该水平的必要前提；不证明它们无效或没有继续提升空间 |
| 预训练太少/越久越好 | 本轮400源就能接近锚点；既有1600未见FT稳定增加 | 不能把重建loss降低等同于迁移更好；本轮未单因素比较SSL轮数 |
| FT超参不同 | 恢复前后我们自己的训练配置相同；与官方锚点的batch、种子、精度、增强、归一化、选择方式仍不同 | 没完全排除，也没必要为开发资格穷举消除所有差异 |

因此，最直白的回答是：**先前“远差于官方”的印象包含指标与人口不匹配，分割训练又确实少用了很多监督。把这些实现问题修好后，现有400轮权重已经能做到接近93%的完整TEST全局Dice，不需要先推翻递归模型或追加一轮预训练才能建立能用的基线。**

不能说“性能下降100%与架构和参数无关”。能说的是：**这些因素不再构成‘当前干净基线必然低很多’的已观察障碍；下一步可以回到用户选定架构的创新，而不需要继续无休止地排查是否能达到93。**

## 10. 论文表述与尚未证明的边界

1. 我们SSL使用全10030个视频的无标签图像，包含后来的监督VAL/TEST视频，属于`transductive_all_splits_unlabeled`。不是监督标签泄漏，但也不是严格未见图像的归纳式TEST；论文必须披露。官方权重的上游数据暴露需另据作者配置确认，不能默认完全匹配。
2. 官方锚点是发布权重的本地单帧实现移植，并非本轮重新完整预训练EchoCardMAE。已有源码前向、损失、梯度与一步AdamW一致性测试，不等于作者运行环境逐项相同。
