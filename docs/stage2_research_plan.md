# 二阶段研究目标对齐与三个验证方向

日期：2026-09-28。状态：目标按用户最新澄清记录；下述具体比较、预算和结构均为待确认实施建议，不是已启动队列。本次只核对资料、形成方案，不修改或重启服务器任务，不修改Excel的核心实验记录及锁定预测。

## 1. 目标与执行权边界

原始交接文件是 `心超MAE时域研究_三阶段计划与CODEX交接_20260928.md`。其第7.4节包含预训练内部帧级展开，第7.5节包含tubelet1参照，第7.7节包含与整窗联合编码比较。之前的提前诊断只覆盖部分接口问题，不替代完整二阶段，也不能据一次offset小头阴性结果删除tubelet研究。

用户当前确认的核心目标：在同一心超自监督预训练编码范式下，保留目标帧空间信息、近期运动信息与有限长期历史；允许下游使用不同读出，不强迫所有任务读末状态。研究不仅为EF或分割刷单项成绩，未来还可能验证其他疾病/风险任务，但现在不提前宣称跨任务通用。

三个问题组：

1. 短VideoMAE+长RVM能否输出以指定帧为锚点的空间特征，其他帧作为上下文，而非只能输出片段整体描述？tubelet与共享帧级接口在本组确定。
2. 递归建模对EF的可读性、迁移效果和资源成本有什么影响？是否需要保留近期多片段输出，而非强迫末状态/末片段独自承担EF？
3. 固定容量的近期特征缓存与更早RVM历史是否互补？可否以有界内存、逐段更新提供更好的功能表示？

Agent可以提出实现候选、便宜诊断与阶段顺序建议，不能把建议自动升级为用户确认的研究目标，不能因省预算永久删去整窗参照或tubelet候选。昂贵训练的实际队列另列并确认，不将三组问题扩成默认全排列。

当前一阶段按最近确认的预算运行：L8/L16/L32、总64帧、stride1、固定spatial、各100轮。它只回答此设置下的时间分工，不回答任意采样间隔、任意状态、任意任务的唯一最佳长度。此文不改变正在运行的一阶段。三阶段边界：阶段一选时间尺度；阶段二确定共享表示接口及读出需求；阶段三优化状态写入、组织、容量与更新。

## 2. 现有结果能说什么

已有冻结诊断支持继续保留目标位置而不是仅用片段均值，但没有证明目标帧结构信息完整。局部/融合差异区间跨0，不能证明融合有害、有效或等效。偏移bank在固定200步探针预算下较差，不证明经过共享预训练的帧级展开无效，也不证明tubelet1没有价值。

当前普通EF聚合所有融合输出F1...F4，不能用其成绩回答只保留F4是否足够。此前state EF聚合状态轨迹，也不等于最终状态S4。当前模型调用每64帧重置，没有实现跨任意长输入的持久状态接口。

## 3. 问题组A：逐帧锚定的空间表征

### 3.1 要求

一次共同的编码过程为所有输入帧形成可索引的表示，分割头选择目标时间位置。目标索引不是ED/ES身份输入；不为分割临时额外训练另一套完整encoder。邻帧信息混入目标表示不是失败，目标结构无法可靠读取才是待解决问题。

需要分别核验：空间边界可读性、帧身份/时间对齐、上下文帮助或干扰、不同片段边界与允许延迟下的稳定性。特征有变化或两头输出不同不等于语义上已区分两帧。

### 3.2 低成本诊断

- 复用已做的目标位置/片段均值、local/fused，不原样重复。
- 同一真实标注帧处于tubelet两个偏移时分别评估；报告来源帧、实际前后上下文，不能把采样窗口变化偷偷算成纯offset因果效应。
- 同一目标图像搭配真实邻域和重复目标图像邻域，各自拟合同规则读出。此项是输入分布干预，不叫严格单帧MAE基线，也不替代匹配预训练。
- 检查探针训练曲线；尚未稳定时可在同一缓存特征上延长训练，不先加新MAE预训练。
- ED/ES分开、按患者汇总；主指标Dice，补充边界误差（像素单位，不编造物理spacing）、低分病例分布与叠图。
- EchoNet的稀疏真值只能直接验证真实标注帧。未标注帧的预测连续性/可视化是诊断，不是整段逐帧准确率，禁止用伪标签证明精确逐帧能力。

### 3.3 必须保留的结构候选

| 候选 | 共享处理方式 | 作用与限制 |
|---|---|---|
| A0 现有tubelet2 | 视频联合编码后，按目标tubelet读出 | 成本低；直接重复输出没有帧内区分 |
| A1 tubelet2+共享帧级展开 | 编码后以帧内偏移投影/重排形成两张图，参与预训练和下游 | 不新增完整encoder；不能凭两张图不同就证明恢复细节 |
| A2 tubelet1 | 输入端保留每帧token位置，仍做共享视频编码 | 明确的结构参照；token与计算增加，需实测 |

A1不是上轮只在冻结特征上训练offset分割头。它必须进入共享MAE的学习路径，并接受保留原始帧差异的目标，才是在测试帧级预训练接口。hidden区域只能通过合法的mask/query恢复，不能通过原图旁路泄漏到encoder。

A2保留为重要参照，不能以“贵”或旧offset探针阴性将其移出阶段二。先做小预算可行性/吞吐，再按一阶段选出的局部长度建立必要匹配对照，不把所有长度乘所有tubelet全部跑完。初始化映射、mask单位、损失分母与输出时间顺序都要显式记录。

一个实际可行的执行建议是：先审计A0及便宜读出，随后对A1和A2做短冒烟/成本测量，确认预算后选择A0与首要候选做匹配探索；如果仍无法判断tubelet限制，必须保留A2的正式参照需求，不用探针结论冒充其结果。

## 4. 问题组B：EF需要访问什么

| 名称 | 预测头访问 | 主要问题 |
|---|---|---|
| B-last | 最后片段融合输出F4 | 历史经过状态后是否在当前位置可读 |
| B-cache | 最近四段融合输出F1...F4 | 保留近期输出是否更有利于功能估计 |
| B-state | 最终状态S4 | 末状态的可读性；仅辅助，不作主模型成败条件 |
| B-joint | 相同64帧一次性联合encoder输出 | 分段递归相对整窗联合建模的真实差异 |

前三项能先用同一权重/同一64帧提特征，各自拟合相同预算的任务头。先用明确固定汇聚及同维输出，必要时才用参数/训练预算可比较的轻量学习型聚合。不要将输入维度更大、头更多参数的收益全部说成信息保留更好。

缓存粒度分清：每clip一个向量；每tubelet一个空间平均向量；完整时空token。每clip一个向量可能已取消显式段内时间位置，因此建议优先保留每tubelet时间序列，再由任务头学习汇聚，而不是先认定一个向量必然足够。

B-joint不能靠直接延长已训练16帧模型的位置编码来建立公平基线；需要匹配初始化来源、样本、时间跨度、目标、优化/训练预算的一项整窗训练参照。原生输入长度变化还须检查预训练权重继承。它是重要对照但不必成为正式部署分支；本次不启动。

评价保留EF MAE为主、RMSE/相关性为补充、按患者配对差异和误差分布。EchoNet的EF标签是视频/病例级，不能当作每个滚动小窗口的独立时变EF真值。窗口数量、视频级汇聚和起点一致；低成本筛选后，关键候选与基线做成对迁移验证，不能凭弱线性头宣布某类建模根本不适合EF。

可能结论：B-cache胜过B-last说明近期输出访问有价值，不否定RVM；B-cache接近B-joint且资源更省支持分段缓存方案；只在强读出头下改善说明需区分信息不足与可读性；多轮尝试阴性也只能界定当前设计、预算与任务，不是全架构不可能定理。

## 5. 问题组C：近期缓存与更早历史是否互补

### 5.1 时间轴必须真实分开

```text
较早前缀P（例如另64帧） -> S_boundary
最近窗口W（4个16帧clip） -> Z1...Z4（局部）/F1...F4（融合）
EF读出 <- 最近窗口缓存 + S_boundary
```

如果只输入64帧，缓存也是64帧，起点S为零，就没有额外的更早历史。若拿末状态S4称“缓存之外的长期历史”也不严谨，因为它包含近期四段。必须明确状态截止时间。

现有F已吸收之前的S，因此“只用F缓存”不是严格没有历史。初步主比较可以是在同样上下文化F缓存上增加显式边界状态，回答其增量可读性；要隔离早期历史的信息贡献，另用未融合局部Z缓存+边界状态作诊断，或做明确的受控历史干预。两种结论不得混写。

### 5.2 首轮建议

- 固定最近窗口W、标签、样本与缓存容量，比较缓存读出与缓存+边界状态读出。
- 控制头参数：使用同结构读出，状态槽位的真实历史与预定义空历史条件比较；冻结诊断需分别训练读出，推理干预和正式匹配训练区分报告。
- 可辅助比较同患者真实前缀与受控替换前缀，但这有分布变化，不能独自证明学习了正确运动机制。
- 对历史不足样本记录真实帧与状态可用性，不能循环重复造历史；同一配对用相同样本。完整历史子集结论单列，不冒充整个数据集。

实现前需增加明确的state-in/state-out接口、跨患者reset、缓存FIFO与时间戳/有效性管理；历史写入和下游查询必须分离，避免预测同一时刻EF时再次把同一clip更新进状态。

在旧64帧训练模型上延续到128帧属于推理长度外推，先标为可行性诊断；不能据此宣称长程状态已训练充分。若有信号再做匹配的更长跨度训练/截断BPTT验证，不能将外推失败直接判作长期记忆无效。

### 5.3 LV-MAE借鉴的边界

原论文的做法是先用短视频编码器获得片段embedding，再对embedding序列做掩码重建，学习片段之间的依赖。它不是把全部像素token拼到一个超长encoder里。[论文](https://arxiv.org/html/2504.03501v2)；[官方仓库](https://github.com/amazon-science/lv-mae)。

本项目可借鉴“在紧凑片段描述上学习长程关系”的层级思想：先试小型时序聚合器读取缓存与状态；若确实有价值，再考虑自监督的片段特征掩码目标。后者是新增预训练目标，必须与仅监督训练EF头区分，不预设为必须新增的第四个方向。

不照搬其自然视频片段长度/语义压缩尺度，不据其结果断言心超逐帧分割或因果流式成立。若缓存使用融合特征，过去被mask片段的信息可能已经进入状态或后续特征；设计embedding重建时需审计这种信息路径。冻结纯局部embedding是更容易控制泄漏的首个诊断载体，但不代表最终必须冻结骨干或照搬LV-MAE。

缓存存储固定，但学习型读出有时间成本；小型聚合应实测更新频率、吞吐和p50/p95时延，不能承诺免费。仅增加缓存的监督收益属于接口/读出证据，不自动成为MAE预训练创新。

## 6. 逐帧覆盖、tubelet与稀疏-稠密结合

### 6.1 三个问题不应混为一个

1. 每一帧是否进入过模型，形成可索引表示？
2. 每一帧何时输出，允许看到多少后续帧？
3. 重型时空注意力是否必须逐帧运行？

逐帧覆盖不要求重型Transformer为每帧独立重跑。tubelet1也不自动产生严格因果性：局部双向注意力仍需等待该片段内的后续帧。tubelet2可以尝试帧级展开，但是否足够准确必须由问题组A验证。

### 6.2 合法的候选

| 路线 | 如何覆盖每帧 | 主要代价/待验证点 |
|---|---|---|
| 稠密tubelet1联合编码 | 每帧进入独立初始时间位置 | token更多；仍需约定分段等待 |
| 稠密输入tubelet2+帧级展开 | 每帧被输入投影看到，随后学习帧内分离 | 便宜一些，但不保证保留所有细节 |
| 轻量稠密空间路径+较稀疏重型时序路径 | 每帧有轻量图像证据，以最近可用时序/历史上下文更新 | 新的共享预训练结构，防止稀疏路径失去作用、隐藏像素泄漏或空间路径独自包办任务 |

第三条是研究候选，不是“完全跳过某帧，再凭插值保证该帧准确”。轻量路径应从预训练起就存在、服务统一输出，不能到分割下游临时补一套完整单帧encoder。因果版本只能使用当时已有的时序状态，等待未来上下文的版本必须报告延迟，不能混报。

简单stride4丢帧无法对未观察帧提供直接证据。预训练稀疏、下游稠密改变时间尺度，必须记录真实时间戳/间隔并验证，不将形状兼容等价于语义兼容。

VideoMAE也可以按滚动/非重叠窗口在线处理，不是必须等整段检查录完才能调用。RVM的潜在优势是有限持久状态使跨窗历史可用、减少重复编码需求；需要同等待待预算、同输出频率、同缓存预算的实际测量来证明。当前64帧重置实现不是完成了这种部署。

有限缓存只能随时取最近保留范围的特征；要无限期回查任意过去帧，应归档帧级输出/特征或重新读取原视频，不能同时承诺固定内存且所有旧帧永久可查询。可逐帧输出后外部保存结果，不要求所有结果常驻GPU。

## 7. 更多下游任务的约束

建议共享接口保留：目标时间位置的稠密特征、带时间索引的近期描述序列、有限历史状态及有效性信息。任务头按需要读取，避免从预训练起就只留下EF专用一个标量/向量。

不同疾病/风险任务可能需要结构、运动、跨周期统计、多个视角或其他模态，不能靠EF+分割成绩替代这些验证。未来另用相应数据和患者划分检验，明确标签时间范围和可用视角；现在不擅自下载或运行EchoRisk，不承诺一个单视图时序接口覆盖全部需求。

## 8. 执行顺序与产物

近期建议先完成一阶段，固定一个或两个代表局部长度。二阶段先实现共同缓存/状态与帧索引审计接口，复用旧权重跑问题组A/B/C能完成的冻结诊断。随后按证据和预算选择必要匹配预训练：帧级展开/tubelet1、整窗64参照、缓存+历史候选，不自动全排列。

每组问题必须输出：实际输入时间范围、可用历史/未来、读出允许访问的信息、训练预算、逐病例预测、性能/成本和替代解释。昂贵候选只在最小验证有信息量时扩展；可以得到阴性结论，但不能用较弱探针阴性替代更强结论。

本文件不写用户实验预测、不锁定成功阈值、不填核心实验执行记录。具体启动清单须与用户确认，确认后才实现和调度新训练；后续实现应逐项对应三个问题，不将它们再次替换为单纯模块消融或内部状态评分。
