## 实验职责

| 任务 | 变更与证据 | 如何影响下一步 |
| --- | --- | --- |
| 现有1600轮FT模型补TEST | 只读VAL选出的两个最佳权重，分割及EF | 补齐当前模型的终点成绩；不在TEST选参数 |
| 官方权重分割锚点 | 已有官方ViTSeg2D移植、单帧、完整标注、官方归一化和pad/crop、Dice/固定AdamW | 若明显低于可靠官方记录，先核查通用迁移/数据/训练流程，不急着新预训练 |
| 已有400轮SSL恢复监督后分割FT | 编码器、状态、近期缓存、头不变，只恢复监督覆盖及必要边界处理 | 看原共同VAL是否改善；不是“只加数据”的纯单因素因果证据 |
| 完整VAL补充评估 | 不重新选权重；报告完整覆盖及旧共同上下文子集 | 区分覆盖扩大与旧病例真实改善 |
| 新模型TEST | 默认执行；VAL最佳权重锁定后才打开TEST | 形成终点交付，不参与后续超参搜索 |

实际复用旧的独立400轮完整日程权重：cr_patch8_w64_400_v1/pretrain/epoch_0400.pt。
不是1600轮轨迹中途快照，不重跑400轮MAE。原common VAL基准也来自这个400轮实验。

## 监督与边界规则

完整监督manifest从原始FileList/VolumeTracings构造，保留至少有1帧视频的有效病例，
沿用原生112坐标、官方栅格化。不存在的视频、无效元数据和异常GT仍明确报告或拒绝；
“完整”不是伪造缺失文件或悄悄修坏GT。
manifest中的旧seg_not_complete_all_positions诊断项仍可用于统计旧规则丢了什么；
恢复数据集不按这些旧上下文诊断项删帧，实际训练覆盖由coverage.unique_source_frames及records记录核对。

- 原本可用的训练帧：沿用旧dataset的取窗、目标位置轮换与增强种子；单元测试逐样本验证一致。
- 新恢复帧：取截至目标帧的16/32/48/64帧上下文，不读取目标帧之后的帧。
- 最早期不足16帧：只在左侧复制该视频第0帧补成一个clip。记录真实frame_indices和补帧数量。
- 标签始终对应原始真实标注帧。补帧不能叫“真实历史”，也不能把这次修复称作新增单帧表征算法。
- 不改tubelet2、repeat展开、递归压缩或分割头。

完整训练池增加后，不直接把每个更大的epoch当作原epoch：
每个virtual round仍取原训练集一样多的样本，保持相同有效batch、更新数/检查和早停耐心次数。
对完整训练池连续做确定性随机排列，跨round游走；一轮排列耗尽前不重复抽样。
因此大部分病例可在前几个round遍历，并非每轮只反复选一个固定小子集。

验证选权重仍使用原来的common VAL、全部合法16个位置。完整VAL另做一次前向，绝不反过来换best。
完整VAL/TEST按位置→源帧→患者汇总，同一源帧的重复位置不增加其权重。
额外提供coverage_kind、补帧数量分层，以及旧上下文共同子集成绩。
不同覆盖人口的总分不能直接当作同人口提升。

## 官方锚点不是另一个隐形改版

使用models/echocardmae_official.py已有单帧移植，不通过递归编码器。
本地测试用已下载作者vit_seg.py/utils.py，严格复制同一state_dict，比对：
前向logits、前景/背景Dice loss、参数梯度及一次相同AdamW更新。
此测试不需要新预训练，也不需要云端再clone作者仓库。
实际本地官方发布权重已核对：214个匹配张量加载；两个正弦位置参数在该文件中缺失、
3D→2D patch卷积及任务输出头按官方分割方式新建。其他编码器/decoder缺项会报错，不能随机继续。

锚点训练：batch64，LR1e-4固定，WD1e-4，betas(0.9,0.999)，无warmup/梯度裁剪，
单帧官方mean/std，归一化后等效零值pad12再随机crop112；VAL监控loss，min25、patience25、max1000。
与作者运行器仍有明确区别：复用本项目执行器、保留尾batch、执行参数/精度探测；
灰度缓存repeat3不冒充原始RGB像素逐值相同。它是实现锚点，不伪称完整官方运行器复现。
如果结果异常，先查这些已披露差异，不能据此立即否定官方复现或递归方向。

## 云端入口

实例恢复且没有旧队列运行时再pull。测试和训练均自动显示进度，结果和权重分离。

```bash
cd /root/autodl-tmp/EchoRVM
git pull --ff-only
export PYTHON=/root/miniconda3/envs/echocardmae/bin/python

# 只检查计划，不分配GPU训练
bash scripts/run_segmentation_gap_stage1.sh plan

# 冒烟成功后再执行第一关完整队列
bash scripts/run_segmentation_gap_stage1.sh all
```

官方权重默认ckpt/mae/EchoCardMAE.pt；如实际文件名不同，必须显式指定：

```bash
bash scripts/run_segmentation_gap_stage1.sh all --official-checkpoint /实际路径/EchoCardMAE.pt
```

支持参数：

- --source-root：旧patch8结果根目录，默认/root/autodl-fs/outputs_cr_spatial。
- --source-tag：默认cr_patch8_w64_400_v1，提供源MAE及原common VAL参照。
- --current-tag：默认cr_patch8_w64_1600_v1，用于补当前模型TEST。
- --root：本轮输出，默认/root/autodl-fs/outputs_cr_gap。
- --tag：默认seg_gap_stage1_v1；正式变更实验条件必须换tag。
- --reuse-anchor：可复用本实现已完成、带DONE和协议的官方锚点stage目录；原始日志不能伪装成同协议可复用产物。
- --development-only：显式不测新候选TEST；状态与报告会标development-only，不得作为论文完整交付。

启动前检查源结果完成标记、400轮权重及官方权重路径。缺权重直接报错，不用随机权重悄悄继续。
冒烟只访问TRAIN/VAL小数据，不提前用TEST调试。默认run先补当前TEST，然后官方锚点和覆盖FT，
再完整VAL，最后新模型锁定TEST。任一任务失败即停止后续任务。

自动调优仍由既有pipeline在正式训练前实测micro-batch、workers、线程、重计算。
恢复后复用保存的执行分组；有效batch/LR/更新预算不由速度探测擅自改动。
锚点不支持重计算，因此不把重计算候选冒充可用配置。

## 输出与完成验收

输出根目录下：

- result/seg_gap_stage1_v1_official_anchor/official_seg_ft：锚点训练过程、指标、预览。
- result/seg_gap_stage1_v1_coverage/seg_full_coverage_ft：恢复覆盖训练与common VAL。
- result/seg_gap_stage1_v1_coverage_val_full：完整VAL及共同上下文子集。
- result/*_test：锁定权重后的TEST；两个新任务各独立结果。
- ckpt/同名tag/：权重和恢复状态。
- control/seg_gap_stage1_v1/：实际配置、接续状态、common VAL对照comparison.json/md。

原1600轮TEST仍写回它自己的source-root/result/cr_patch8_w64_1600_v1_test，不混进新FT。
只有默认run中要求的TEST都成功并写完汇总，控制状态才能done；
不能仅凭训练stage DONE或有best.pt宣布论文评估完成。
默认不自动关闭/释放实例，不重新启用旧巡检任务。

现有重建与FT完成产物的协议验证也修正：先校验科学身份和DONE，再复用；
不再因为运行环境记录变化先覆盖旧protocol.json，导致已完成结果哈希被自身改坏。
