## Git 设置

- `.gitignore` 仅放行这份主表、协作协议、本说明及 `docs/AGENTS.md`。其他私有资料仍保持原忽略规则。
- `.gitattributes` 将 `docs/*.xlsx` 标为二进制：不转换换行，不进行文本 diff 或文本自动合并。
- 文件较小，使用普通 Git 保存版本，不启用 Git LFS，不增加安装和远端配额依赖。
- Excel 的 `~$` 临时锁文件、outputs 备份和预览不提交。
- 当前远端为 `origin`，对应 `https://github.com/MisakuraPW/EchoRVM`，与训练代码是同一个 GitHub 项目，不另建表格仓库。
- 用户已授权：Agent 完成获准的代码或研究记录修改并验证后，自动提交、推送本轮文件。可以分开提交，但不能把已完成的表格更新仅留在本地暂存区。此授权不扩大核心实验记录、锁定预测等内容的编辑权限。

## 双人协作

Git 不支持像在线 Excel 那样实时共同编辑。双方约定一人一轮编辑，开始前确认表格没有未提交修改，再执行：

```bash
git pull --ff-only
```

修改后关闭 Excel，确认保存完成，再只提交本轮相关文件。例如仅修改表格时：

```bash
git add -- "docs/心超MAE_研究记录.xlsx"
git commit -m "docs: update MAE research record"
git push
```

接手前等待对方 push，再 pull。若本地已有未提交修改，不要直接 pull、reset 或覆盖，应先保存自己的版本并协调顺序。

若双方都改了同一版本，Git 无法按单元格合并。保留两份冲突版本，比较想法/实验 ID 和修改区域后人工合并为主表，不能静默使用 ours/theirs，也不能 force push 解决内容冲突。

## Agent 写入检查

1. 读取最新主表和编号，保留人工新增内容，不从旧模板重新生成。
2. 写入前在被忽略的 outputs 中留备份，并确认主表未被同时修改。
3. 按范围更新，保留公式、表格、验证和原始格式。核对旧记录与核心实验锁定区。
4. 写入后检查可读性和公式，明确事实、假设与待确认建议。
5. 仅暂存本轮文件，不顺带提交代码、权重或整个 docs 目录。
